# 星译官 StarTranslator

<p align="center"><img src="renderer/assets/app-icon.png" alt="星译官" width="112"></p>

**译步到位。** 面向中英技术资料的文档翻译与审校工作台，由 **MathiasCym** 维护。

支持中英技术材料双向翻译，也可直接输入文本；结合参考原稿与专业术语库审校中文或英文，逐条确认修改。支持 Office、PDF 文字层、文本、电子书和字幕；既可在自己的电脑上使用，也可通过局域网共享工作台与同事协作。

当前版本为 **2.3.3**。术语库新增 8 种语言的只读查阅和跨语言搜索，保留原表全部 1,965 行及各语言缺译空项；中英翻译词库仍为 2,515 条，文档及自由文本继续支持中英双向翻译。模型配置不设数量上限。本机数据目录统一使用 `StarTranslator`，安全迁移已有词库、加密配置和历史，保留旧路径兼容链接。局域网协作将其他网卡地址折叠，减少开启共享后的多余滚动。各文档格式独立处理，PPT 保留逐样式翻译、原生渲染和模型版式审查。PDF 文字层输出重新排版的 Word，英译中暂不改写图片内英文。正式下载以发行页已发布版本为准。

本批范围与验证见 [2.3.3 验收](docs/validation-2.3.3.md)。GitHub 与国内增量渠道均已正式发布；2.3.2 用户可在软件中检查更新，下载约 1.59 MB 的小包，首次安装仍使用完整安装包。多语言查阅入口位于“术语库”窗口的词库文件栏，支持任意语言关键词或按语言筛选，仅供查看和搜索。

## 功能一览

本次功能与使用范围见 [中英双向翻译](docs/bidirectional-translation.md)，正式入口及旧版小包升级记录见 [2.3.2 验收](docs/validation-2.3.2.md)，此前正式包见 [2.3.1（原 2.2.7）验收](docs/validation-2.2.7.md)。已有本机词库的补全机制见 [本机词库自动补全](docs/bundled-glossary-updates.md)，此前正式附件及实际升级记录见 [2.3.0（原 2.2.6）验收](docs/validation-2.2.6.md)。

| 功能 | 可以完成的工作 |
| --- | --- |
| 自由文本翻译 | 输入或粘贴文本，选择中译英／英译中；复制、交换文本，取消或断连后单独重试未完成部分。 |
| 文档翻译 | 翻译 Word、PPT、Excel、PDF 文字层、文本、Markdown、HTML、JSON、EPUB 和字幕，结合参考材料与术语库按所选方向生成中文或英文。 |
| 中英文审校 | 英文先进行术语规则检查，再按需调用模型检查表达与原稿一致性；中文由模型审校，建议经用户确认后保存。 |
| 全文一致性 | 跨页复用重复原文的译法，检查术语和时间标题写法混用，在报告中确认统一。 |
| 翻译并校对 | 一次启动两个阶段；可仅保存最终文件，也可保留翻译文件和校对文件。 |
| 校对报告 | 查看上下文、编辑替换文本、选择建议并确认保存；支持已替换 / 未替换筛选。 |
| 中英对照 | 左右查看完整原稿与处理后页面，支持同步翻页、滚动、缩放，以及可搜索的文字对照。 |
| 术语库 | 搜索、普通术语／人名分类、列表与表格编辑、导入导出，以及团队词库差异预览和冲突处理。 |
| 局域网协作 | 一台电脑提供模型与词库，同事通过浏览器或已安装的星译官提交异步任务。 |
| 历史与维护 | 按日期查找任务和输出位置；导出诊断日志、校验组件完整性并尝试离线修复。 |
| 本机断点 | 断连、取消或重启后复用已完成的译文与审校段落，从历史记录继续未完成任务。 |
| 界面适配 | 窗口随屏幕可用空间与 Windows 缩放适配；文字保持清晰，列表紧凑排列，常用操作直接可见。 |

**软件不设注册或登录。** 普通使用、获取公开团队词库和检查更新无需 GitHub 账号；提交词库修改需要维护者授权。模型服务可能需要自己的接口密钥，安装包不包含模型权重或云端模型额度。

## 快速开始

桌面安装包面向 **Windows x64**，随包提供 Python、文档处理库和 OfficeCLI。使用安装版无需另装 Node.js、Python、Git 或 Office；目前未提供 macOS / Linux 桌面安装包。

1. 首次安装从 [GitHub Releases](https://github.com/MathiasCym/StarTranslator/releases/latest) 的 **Assets** 下载 `StarTranslator-Setup-<版本>.exe`。已有 2.0.10 或更新版本时，优先在软件内获取国内小包更新。`.stpatch` 是供软件使用的增量数据，`Source code` 是源码，两者都不能当作首次安装包运行。
2. 运行安装包，选择位置和安装范围。“所有用户”安装需要管理员授权；升级会识别既有安装，保留配置、词库和历史记录。
3. 等待安装完整性校验通过，再启动星译官。安装目录默认使用英文名称 `StarTranslator`。
4. 打开“模型设置”，填写连接信息，先“保存配置”，再“使用配置”。
5. 选择“翻译”或“校对”，确定翻译方向或校对语言后添加文档；需要时加入对应原稿、定稿或双语参考资料。直接处理粘贴文本时打开“文本翻译”。
6. 开始任务，完成后查看结果或报告，确认修改并保存，再打开文件检查内容和版式。

仅进行英文术语规则检查时可以关闭“深度审校”，无需模型服务。翻译、深度审校及中文语义审校需要可用的模型连接。

每次启动都会在后台检查正式更新，发现新版本时简要介绍重点变化；可勾选“此版本不再提示”，不影响后续其他版本的提醒，也可随时在“关于 → 软件更新”中手动检查。提醒不会自动下载或安装，不会在文档处理或其他窗口操作过程中打断工作。翻译方式旁的问号会打开独立说明窗口，关闭后回到原位置。

2.0.10 起支持小包更新：匹配最近三个版本时只下载变动数据，国内来源不再每次重复上传完整安装包。2.0.9 及以前版本需先使用 GitHub 完整安装包升级一次；首次安装、跨越较多版本和修复仍使用完整包。软件会显示更新类型和下载大小，并在安装前后校验，模型配置、词库和历史记录保留。

如果 2.0.10 / 2.0.11 点击“关闭并更新”后没有启动，可以从正式发行版下载与当前版本对应的 `StarTranslator-SmallUpdate-<原版>-to-<新版>.exe`，退出星译官后运行。它包含相同的小更新数据并修复启动方式，复用本机运行库，无需再次下载完整安装包。2.0.12 起内置更新会显示合成、替换、校验进度并自动重启。

## 模型配置

| 连接方式 | 配置说明 |
| --- | --- |
| 公司内网模型 | 新建时预填内网接口地址；模型名和密钥按公司提供的信息填写，并确保网络可达。 |
| 其他兼容模型 | 连接字段默认留空。DeepSeek、Qwen 或本机模型服务均按其实际兼容接口填写。 |

其他兼容模型可选择 **OpenAI** 或 **Anthropic** 接口格式。Claude 原生接口使用 Anthropic；中转服务按服务商说明选择格式及密钥发送方式。

左侧配置列表用于查看和编辑，**保存配置不会切换当前模型**；点击“使用配置”才会切换连接并关闭窗口。右上角状态自动检测，鼠标悬停可查看详情。不支持轻量模型列表检测的接口可能显示“待确认”，实际调用结果以任务为准。

模型的权限、额度与费用由相应服务方决定。局域网使用者不必重复配置模型，任务使用共享电脑当前的连接。

## 使用流程

### 翻译与参考材料

待处理文档与参考资料支持下表格式，桌面与局域网入口一致。可以添加多份文档，并选择其对应中文原稿。

| 输入格式 | 输出与保留范围 |
| --- | --- |
| Word `.docx`、PPT `.pptx` | 沿用原有正文与样式处理；PPT 在原文本框内适配英文。 |
| Excel `.xlsx` | 输出 Excel，仅改写文字单元格，保留公式、数字、工作表名、单元格样式和其他包内容。图表、图片及文字内部的多种强调样式不重建，长译文需检查行高列宽。 |
| PDF `.pdf` | 本地读取文字层，按原页顺序重新排入可编辑 `.docx`，保留可读取的图片、原链接和页间跳转；不还原原 PDF 版式或复杂表格。图内中文仅在可安全定位、覆盖并核验时处理，未完成位置明确提示。没有文字层的扫描件或需要密码的文件会给出具体提示。不能将 Word 结果覆盖到 PDF 原稿。 |
| 文本 `.txt` | 保留编码和换行，支持 UTF-8、带 BOM 的 UTF-16 和 GB18030。 |
| Markdown `.md` / `.markdown` | 保留标题与列表标记、链接目标、代码块和前置元数据，处理可读正文。 |
| HTML `.html` / `.htm` | 处理正文文字，保留标签、属性、链接、脚本与样式；代码、SVG 和公式内容跳过。 |
| JSON `.json` | 处理字符串值，保留键名、数字、布尔值和结构；网址及路径跳过。应使用文本类数据，避免将程序配置当成普通文档。 |
| EPUB `.epub` | 处理章节正文，保留目录关系、图片、样式及打包结构；不支持受 DRM 保护的正文。 |
| 字幕 `.srt` / `.ass` | 保留序号、时间轴和样式标记；ASS 绘图事件跳过，仅处理字幕文字。 |

旧版二进制 Office 格式（`.doc` / `.xls` / `.ppt`）、图片文字识别和扫描 PDF OCR 暂不包含在此版本中，可先转换为以上格式。

点击“开始翻译”后，译文单独保存，中文原稿保留；未指定输出目录时通常保存在原文件旁。PPT 会在原文本框内适配字号、字体与行距，尽量保持图片及文本框的位置和尺寸。

材料默认来自中国、面向海外读者，涉及“国内”等表达时结合语境明确中国，宣传用语以准确传达原意为准。完成后可继续校对译文。

### 翻译并校对

点击“翻译并校对”，开始前选择输出方式：

| 输出方式 | 文件处理 |
| --- | --- |
| 只输出最终校对文件 | 中间译文在本机暂存，仍参与相同校对与版式处理；确认保存后，目标目录只输出最终文件。 |
| 保留翻译文件和校对文件 | 保存翻译文件，确认建议后再保存校对文件。 |

进度显示翻译、校对、PPT 逐页格式对照和保存等阶段及当前活动。**校对建议不会自动应用**，由使用者查看、编辑并确认；也可以选择保留当前译文。

个别段落有限修复后仍未完成时，其余英文继续校对，未解决的位置逐条列在报告中，允许先保存可用文件；保留的中文不会冒充完整英文或交给校对批量重译。模型断连时保留草稿与断点，条件一致后可继续。文件可以打开并不代表全文已通过翻译或审校，请查看报告中的检查范围和待处理项。

### 校对报告与保存

1. 完成页显示本次检查信息，点击“查看校对报告”打开完整报告。
2. 按类型、替换状态或关键词筛选，查看原文、建议、原因及上下文。
3. 可编辑替换文本，再勾选需要的建议。“全选”选择当前可见且可处理的建议；“选中术语建议”用于选择术语相关项。
4. 单独校对可另存新文件或覆盖原文件；覆盖直接替代，不留备份。翻译并校对按开始时选择的方式保存，中文原稿保留。
5. 已应用项默认从待处理列表隐藏，可通过“已替换”或“全部状态”查看。“打开所在位置”位于报告工具区。

没有建议时可直接保存译文。保存后仍可查看报告；切换功能或返回时，会按未保存结果和待处理建议提示确认。部分检查未完成时，请查看报告的检测范围。

### 完整页面与文字对照

从结果或历史记录打开“原文与译文”：**页面对照**左右显示完整原稿与处理后页面，包含图片、表格与图表，支持同步或独立浏览；**文字对照**用于搜索和定位文字。

预览由 OfficeCLI 生成，不调用模型，也不会修改文档。特殊效果、缺失字体和复杂公式可能与 Word / PowerPoint 显示不同，最终版式以导出文件为准。图片文字及复杂嵌入对象仍可能需要人工处理。

新增格式提供文字对照和明确标注的“正文阅读预览”，不冒充原文件的完整视觉版式。PDF 对照的中文侧直接显示原 PDF 页面，保留原版式、图片和表格；英文侧按当前输出的 Word 文件预览，两侧分别显示实际页数。原 PDF 逐页读取，无需 Office；页面读取失败会明确提示，仍可切换文字对照。

### 全文用语统一

翻译时，同一文档跨页重复且只有一种文字样式的完整原文可复用译法；各段保留自己的字体样式，不额外调用模型。混合样式、歧义术语和无法确认对象的量词分别处理。

校对会检查明确配对的相同中文原文、词库已认可写法的混用，以及 `H2 Strategy` / `Second half Strategy` 等时间标题差异。建议单独标为“全文一致性”，可筛选、编辑并确认应用，不自动替换。词库已确认标准优先；没有标准时参考该文件已有译法。单独翻译的结果页也会提示可继续校对的一致性建议。

检查通过本机脚本完成，并将必要的统一建议加入原有审校请求，不增加模型请求次数。缩写与全称的合理搭配、不同文件或不同计数对象不会被强制统一；没有对应原稿、无法确定含义的自由表达仍需人工判断。

## 团队词库维护

词库支持列表和表格编辑。标准英文、正确别名、已确认错译、机翻候选与备注分别维护；缩写全称可放入正确别名，每行一个写法。修改后点击“保存词库”。

人名可在详情右上方或表格“分类”列选择 **人名**，填写团队确认的英文拼写及姓名顺序，其他允许使用的姓名写法放入“正确别名”。搜索旁可筛选全部、普通术语或人名。JSON、Excel、CSV、TSV 及团队同步均保留分类，旧词库缺少分类时按普通术语读取；不会自动猜测姓名或重写已有英文。维护人名分类的成员请使用 2.2.0 或更新版本，以免旧编辑器保存时丢失新增字段。

### 导入、导出与文件共享

- **导出**：JSON 或 Excel，导出完整词库，不受搜索筛选影响。Excel 使用统一格式，长内容支持换行。
- **导入**：JSON、Excel、CSV 或 TSV。相同词条补充别名和备注，不同译法列出差异供核对。
- **共享文件**：可交给同事导入，也可连接共享盘或网盘同步目录中的词库文件。编辑前重新读取，避免同时覆盖同一文件。

详细说明：[术语库分享指南](docs/术语库分享指南-1.7.0.md) · [词库表格格式](docs/词库表格格式-1.7.1.md)。

团队词库已补充经授权的公司官方英语词条，共 2,515 条；原有确认译法、别名、备注和人名分类保留。2.2.5 起，默认本机词库启动时自动按批次补入缺失词条并备份原文件，不覆盖个人译法或重复恢复已删除的条目；补全结果及分歧在术语库显示。外部 JSON／共享表及后续团队改动继续通过团队同步预览后合并。多语言 Excel 导入识别 `zh-CN` / `en-US` 等表头，其他语言列不会成为备注；原始多语言工作簿不随软件分发。

### 获取公开团队词库

1. 保存本机编辑，打开“术语库 → 团队同步”。
2. 点击“获取团队最新词库”，预览新增、修改和删除的差异。
3. 双方修改相同内容时，逐项选择保留本机或团队内容，再“确认同步”。

获取无需登录或安装 Git。确认前不会修改当前词库；独立的本机修改参与合并。

### 成员如何提交修改

首次配置：

1. 所有者在仓库 **Settings → Collaborators → Add people** 中邀请维护成员，成员用自己的 GitHub 账号接受邀请。
2. 所有者可创建仅选择本仓库、授予 **Contents 读写权限**的细粒度授权。其他个人仓库协作者需在 [经典授权创建页面](https://github.com/settings/tokens/new) 创建具有 `public_repo` 权限的授权，限制见 [GitHub 官方说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#fine-grained-personal-access-tokens-limitations)。
3. 在“团队同步 → 维护授权设置”中粘贴并保存。授权加密保存在该维护者的 Windows 账户中，用于向 GitHub 认证；不写入词库或安装包，失效后重新配置即可。

日常维护：

1. 获取并确认同步最新词库。
2. 编辑词条并保存本机修改。
3. 点击“提交本机修改”，填写维护说明，核对差异并“确认提交”。
4. 提交成功后团队词库立即更新；其他成员再次获取即可使用。“最近维护记录”可追溯作者和维护说明。

软件仅向 [glossary/team.json](glossary/team.json) 提交词库内容，形成普通 Git 提交。词库公开可读；个人文档、模型配置和日志不参与同步。词库更新无需重新发布安装包，也不会自动改写其他成员尚未同步的本机词库。

## 局域网协作

| 使用方式 | 操作 |
| --- | --- |
| 浏览器 | 打开共享电脑显示的局域网地址，无需安装桌面软件。 |
| 已安装的星译官 | 点击“局域网协作”，填写共享地址，打开独立的共享工作台。 |

1. 在共享电脑准备模型与词库，打开“局域网协作”，选择“开启共享服务”。端口为 `1024–65535` 之间的整数。
2. 同事使用界面显示的地址连接，如 `http://192.168.1.10:8765`。`127.0.0.1` 仅供共享电脑自身使用。
3. 上传文档和可选参考材料，选择任务。每次最多 30 份文档，每份不超过 150 MB。
4. 在“我的任务”查看进度，可继续提交或取消任务；最多同时处理两项，其余排队。
5. 完成后查看结果和报告，确认保存，再从报告末尾下载文件。

电脑需处于可互通的局域网，并允许所选端口连接。关闭协作窗口不会关闭服务；关闭共享服务后不接受新访问，已接收任务继续处理。退出星译官会结束服务和未完成任务。

浏览器会话各自保留任务列表。清除站点数据后无法访问原会话任务；共享电脑重启后，已输出文件可从其历史记录和输出位置查找。下载完成后可删除共享任务及文件副本，上传者电脑上的原文件保留。

“并发加速”控制任务内部处理方式，实际速度取决于模型、网络和文档内容，不适合并发的模型可关闭。详细说明见 [局域网协作与中英对照](docs/局域网协作与中英对照.md)。

## 数据与文件

| 数据 | 保存或处理位置 |
| --- | --- |
| 桌面文档与结果 | 保存在本机；翻译、深度审校所需文字和参考上下文发送到配置的模型服务。 |
| 局域网上传材料 | 副本保存在共享电脑，由该电脑调用模型服务并生成结果。 |
| 模型配置与接口密钥 | 保存在配置模型的电脑上，用于相应模型请求，不参与团队词库同步。 |
| 公开团队词库 | 保存在本仓库，免登录获取；维护者确认后提交修改。 |
| 历史与诊断日志 | 保存在本机，可查找输出位置或手动导出诊断。 |

历史记录支持本日、本月、本年和指定时间段筛选。重新编辑旧任务的建议时，请重新校对对应文档。单独校对选择覆盖时会替代原文件；仅保存最终文件也仍需本机暂存译文。

2.0.7 起，翻译与深度审校会将已验证完成的段落保存为本机断点；任务中断后，在失败页或“历史记录”中点击“继续未完成任务”。软件重新读取原稿，复用完成部分，只请求未完成段落；校对建议仍由用户确认。材料、词库、参考材料、模型或翻译方式变化时，旧断点不参与本次任务。旧版本中断前未保存的成果无法追溯恢复。

断点包含文档片段及已生成内容，保存在用户数据目录的 `task-checkpoints.sqlite3`，不参与公开词库或 Git 同步。局域网任务的断点保存在共享电脑；保留原浏览器会话可继续任务，删除最后一个关联共享任务时一并清理其上传副本和断点。

开启并发加速后，同页短段落可共用一次请求，每段仍独立编号、检查并写回原有样式位置，未合并文本框。PPT 的图片、位置、字号和行距由原有排版流程控制；普通翻译保持快速模式，复杂 PPT 段落在内容或样式校验失败后，可使用支持思考的模型进行一次修复。实际速度仍取决于接口响应、网络和所需修复量。

## 常见问题

**安装后还要部署本地模型吗？**

不一定，可以连接公司内网或其他兼容服务。本机模型的运行服务与权重需要另行准备，安装包不包含权重。

**状态灯显示未连接怎么办？**

悬停查看详情，核对接口、格式、模型名、密钥与网络。VPN 本身不作为失败依据；不支持轻量检测的服务可能显示“待确认”。

**文档读取失败或检查组件缺失怎么办？**

确认是完整 `.docx` / `.pptx` 正文文件，排除以 `~$` 开头的 Office 锁文件。在“关于 → 校验完整性”检查并尝试离线修复；失败页可导出错误日志，无法修复时按具体原因处理或重新安装。

**为什么仍有中文，或预览与 Office 排版不同？**

图片文字、复杂嵌入对象及特殊字体不一定能自动处理。查看未处理内容与版式提示，并打开导出文件复核。

**报告没有建议还要点击应用吗？**

不需要，直接保存译文。正确别名不等于错译，是否采纳建议由你决定。

**如何更新软件？**

在“关于 → 软件更新”检查和下载正式版本，校验通过后确认安装。2.0.10 起，匹配的近期版本使用增量小包；原版本不匹配或准备失败时可改用完整更新。2.0.9 及更早版本需要先完整升级一次。安装前完成任务并保存编辑，现有配置、词库和历史记录会保留。

## 开发与发布

每次接手先读 [AGENTS.md](AGENTS.md) 和 [固定工作与发布流程](RELEASING.md)。版本准备、测试、Git 提交、打包、国内补传及交付验收统一按该流程执行。

开发环境为 Windows x64、Node.js 24 与带有 pip 的 Python 3.11。首次准备运行库需联网，运行库和组件版本由仓库固定。

```powershell
git clone https://github.com/MathiasCym/StarTranslator.git
cd StarTranslator
npm ci
python tools/bootstrap-runtime.py
npm start
```

后端回归及安装、更新、日志检查：

```powershell
python-runtime\python.exe -B tools/run-regressions.py
node --test tests/test_release.js tests/test_install_integrity.js tests/test_installation_repair.js tests/test_setup_worker.js tests/test_github_updates.js tests/test_electron_updates.js tests/test_public_sources.js tests/test_domestic_publish.js tests/test_release_repair.js tests/test_runtime_log.js
```

默认提交源码到 `main`，由 Actions 测试并生成源码声明版本的正式安装包。本机打包按需执行；`npm run dist` 等入口会选择未使用的版本，不能当作固定版本的重试按钮。说明和词库变更无需新软件版本。

开发者需配置 GitHub 推送授权，软件内的词库维护授权不自动配置命令行 Git。安装包放在 Releases，已发布版本默认保留。GitHub 和国内渠道分别验收；国内完整下载及旧客户端检查通过后，才报告国内更新已就绪。具体完成条件和交付记录模板见 [RELEASING.md](RELEASING.md)。

国内公开来源的接入见 [国内来源接入说明](docs/domestic-distribution.md)。2.0.10 起，国内仓库只同步经过摘要核对的小更新包和清单；完整安装包在 GitHub 保留。发布验证使用匿名直连下载及独立安装副本，核对实际合成结果和更新缓存清理，不能用页面存在或源码同步成功代替验证。

GitHub 测试、打包和国内增量发布通过后台流程执行。国内附件需要分别完成匿名读取与校验，再设为正式版。词库提交仍连接 GitHub，需要维护者授权和相应网络；国内专用词库分支及维护者审核的提交入口尚未实现。

| 目录 | 用途 |
| --- | --- |
| `renderer/` | 桌面界面、文件选择窗口与共享工作台。 |
| `backend/` | 文档提取、翻译、审校、词库、任务队列和页面预览。 |
| `lib/` | 主进程支持、安装完整性、离线修复、更新与日志。 |
| `glossary/` | 随包词库与公开团队词库。 |
| `tools/`、`tests/` | 运行库准备、构建发布、校验及回归检查。 |
| `website/` | 静态官网和使用指南源码。 |
