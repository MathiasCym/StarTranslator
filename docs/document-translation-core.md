# 文档翻译的共用机制

维护者要求不同语种尽可能复用处理逻辑，同时保留不同文件格式的专用保护。共用流程不等于把英语的“出现汉字即未译”判断套到所有语言。

## 共用部分

| 模块 | 职责 |
| --- | --- |
| `backend/document_parallel.py` | 页／段分组、受限并发、按原文顺序返回、取消、任务与备注范围的线程上下文。工作线程返回数据，文档对象仅由所属线程写入。 |
| `backend/document_translation_core.py` | 请求位置覆盖、未完成位置记录、有限补译、连接恢复后的重试资格、连接中断摘要、已验证文件的原子发布。 |
| `backend/llm/transport_recovery.py` | 模型请求耗尽重试后先冷却等待，再允许一个恢复探针；等待可取消，持续故障停止追加请求。所有语种及文本请求复用同一连接层。 |
| `backend/atomic_file.py` | Windows 短暂占用的有限重试；每次重试重新执行源文件和输出位置检查。 |
| `backend/review_format.py` | 统一读取 Word／PPT 的真实上下标事实，供五种文档校对语言使用；只消除有明确格式证据的重复上标改写，不删除真正的文字改正。 |
| `backend/replacer/styled_text.py` | 统一验证样式映射；仅用于空白的独有样式不能承载新译文文字，避免引入原稿暗色空格的默认色。 |

中译英沿用已经验证的内容和样式处理，在共用调度、覆盖、补译资格与保存上复用上述模块。英译中、繁体、日语和韩语使用同一个有限补译调度器。旧的 `multilingual_parallel.py`、`translation_retry.py` 仅保留兼容导入，不再维护另一份实现。

请求返回、进度达到总数和某些段落出现目标文字，都不能证明全文完成。每个应处理位置必须得到经过对应策略校验的结果，或被明确记录为未完成；不能漏掉未提交的位置。失败补译只处理未完成内容，已经验证的内容不重新翻译。

## 必须保留的差异

- 语种策略：提示、独立语义复核、数词、单位词汇、简繁字形、日语共用汉字、韩语汉字、专名和目标语言判断。
- 格式适配：Word 的目录与流式表格，PDF 的提取、图内文字与输出重排，PPT 的文字样式、颜色、字号、几何与原生渲染。
- 检查点：绑定原稿、模型、方向、格式策略与处理范围；普通新任务不自动复用历史，显式恢复必须重新验证缓存资格。

单位使用共用的数量解析和单位归一化规则，语言差异通过词汇数据补充。例如 `130万像素`、`130萬像素`、`130만 화소` 和 `1,300,000 pixels` 可表示等值数量；错误数量或不同物理单位仍拒绝。归一化只用于检查，不能改写输出文本。

## 中断与输出

请求耗尽重试后，段落层不能立即无上限重试。连接层冷却后允许受控恢复；文档补译阶段最多再处理一次失败位置，仍执行原有内容和样式检查。持续断网时保留可用文件和断点，显示明确的连接中断摘要。未完成翻译的位置不能计入正常术语或语法建议。

保存使用同目录临时文件和原子替换；短暂占用可以有限重试。等待期间原稿改变、目标位置出现新文件或现有输出被修改时必须拒绝覆盖，不能删除外部新建文件。

2.4.1 的有效历史断点按正式原包中的确切策略摘要兼容读取，任务会话与输入身份必须完全相同，且仍执行当前内容校验。普通新任务不能借此复用旧任务。带真实上下标的审校请求补充格式证据；不能因纯文本显示 `109` 就认定文档里的上标已经丢失。

多语言旧断点若整段译文已通过当前内容检查，仅样式对应失效，单段可以复用正文后重新映射样式；不能把整段译文按比例拆给不同来源分块。缺失或不可读的参考文档不提供上下标证据，也不能因此阻止已提供文字的语义校对。

## 验证入口

- `tools/run-regressions.py`：原有文档检查及共用机制的完整回归。
- `tests/test_document_core.py`：五目标语种、Word／PPT／PDF 的受控断线恢复；持续故障、取消、覆盖遗漏和保存竞态。
- `tests/test_multilingual_coverage.py`：等值数量、错误数量、单位、同文复核、目标语言残留及有限补译。
- `tools/check-readable-ui.cjs`：连接中断与普通建议区分、术语标准选择、备注范围及紧凑布局。

离线测试不替代实际模型与原生文档验收。新批次的实际结果记录在 `agent-progress.md` 与 `docs/next-release.md`；没有完整通过时不得称为已经交付。
