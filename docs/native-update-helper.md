# 原生更新辅助程序

2026-11-02，真实 2.3.5 已下载并校验 2.3.6 小包，却在启动辅助程序时失败。只读日志确认没有请求管理员权限，旧错误却将启动失败与授权取消混为一谈。

## 2.3.7 的更新方式

- `build/patch-helper.cs` 编译为原生 Windows GUI 辅助程序；实际启动不经过 cmd、PowerShell 或任何脚本文件。启动前复制校验自己的辅助程序，先核对计划哈希、路径和版本，再确认握手；只有握手成功，主界面才关闭。
- 按原始清单校验安装，验证每个暂存文件后准备恢复资料，等待程序释放文件；保留原文件备份，替换后重新验证目标完整清单。执行中失败恢复原始字节；其他更新或其他实例占用时不强制结束它们。
- 保留进度窗口、恢复登记与自动重启。更新组件纳入安装校验及离线恢复；成功后仍仅清理本程序已验证的缓存和临时资料。启动失败记录实际错误码，不凭猜测显示“取消管理员授权”。
- 不改模型、词库、任务历史、翻译与文档处理路径，也不修改全局代理或系统安全策略。

## 旧版如何带入修复

旧版自己的启动器先失败，就无法安装藏在新小包中的修复。最近三个基线早于 2.3.7 时，正式发布同时生成 `StarTranslator-SmallUpdate-<原版>-to-2.3.7.exe`，嵌入同一原始小包和原生辅助程序，复用旧运行库。退出旧软件后运行一次，之后使用新版内置原生更新。

原始完整包、`.stpatch` 与一次性入口均保持各自已发布字节；国内只复制 GitHub 原小附件和校验信息。此次本地另有已验证的 2.3.5→2.3.6 恢复入口，仅为救援使用，并未覆盖 2.3.6 正式附件；永久交付见 [2.3.7 验收](validation-2.3.7.md)。
