# 安装校验显示与软件内自动修复

已纳入 1.8.6 安装包；既有 1.8.5 安装包未改动，也未安装到当前用户或同事电脑。最终包与独立安装副本验证见 [validation-1.8.6.md](validation-1.8.6.md)。

## 用户界面

- 安装进度增加独立的第四步“校验安装完整性”，显示校验百分比及已检查 / 总项数。
- 安装完成后保留四项步骤、通过结果及检查数量，再允许启动软件；卸载流程仍为三步。
- “关于”提供“校验完整性”按钮，打开带星译官形象的“校验与修复”窗口。
- 开始后依次显示检查、验证修复副本、自动修复、重新校验、OfficeCLI 启动检查等实际阶段。健康文件不重写。
- 未通过时保留具体原因，可直接导出诊断日志。小窗口中原因列表单独滚动，操作按钮保持可见。

## 检查与恢复范围

- 软件内依据同版本安装清单校验已分发程序文件的大小和 SHA256；不把正常可变的 Python 缓存当作损坏。安装结束的校验仍覆盖安装清单中的全部文件。
- 打包流程生成当前版本的离线压缩修复副本，覆盖 OfficeCLI、Python 运行时的固定文件和解包后的后端程序文件；不依赖网络、Python 或 OfficeCLI 来解压恢复。
- 恢复前验证整个副本与清单，单文件解压到同目录临时文件，检查大小、内容校验值及压缩数据校验值，再替换目标；修复结束进行全量运行期复查。
- 缺失的组件目录可以重建。目录占用文件名、目录链接、越界路径、版本不符、损坏副本、权限或占用失败都不能被报告为修复成功。
- 主程序、Electron 核心和应用归档等正在运行的核心文件，以及修复副本自身不进行在线覆盖。它们的问题会显示在报告中并提示使用完整安装包重新安装。
- 文档、导出结果、个人术语库、共享术语表及模型配置不属于恢复目标。修复不改系统安全设置。
- 检查不能在活动翻译 / 校对或保存操作中开始；检查期间拒绝新任务和保存请求。仅修复 OfficeCLI 不重启本地服务；修复 Python 或后端文件需要暂停并重启私有服务，当前报告或编辑状态不允许重启时明确提示先完成处理。
- 校验通过后真实执行 OfficeCLI `--version`，设置禁用驻留与自动更新的环境变量；启动失败与文件缺失分开显示，不假定文件存在就一定可运行。
- 结果写入用户日志目录下 `integrity.log`，已有诊断导出包含该记录。文件恢复但本地服务启动失败时，报告服务恢复未完成。
