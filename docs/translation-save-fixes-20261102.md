## 修复原因与范围

PPT 读取器把“形状支持文本”当成“已有文本体”。读取部分装饰形状会创建空文本节点，导致原有保存保护正确拒绝意外修改。现按实际 XML 文本体判断，包含组合形状与备注占位符。另修正段落百分比间距节点在 DrawingML 中的次序；没有放宽或关闭保存保护。

英译中失败不是单一的模型漏译：短标题曾收到从文档开头截取的全文语境，容易扩写目录和摘要；财务的 `12M FY2025`、`3-in-1` 与“三合一”、代码之后的句号又触发错误的事实校验。现使用 Word 邻近段落语境，短标题仅翻译自身；明确财务标签和三合一的等价表达仅用于比较，型号、数值、单位和原代码仍严格检查。财务 margin 按领域解释，不强用工程术语。中文夹带可识别的完整英文语句会触发重试。

强调映射与内容复核分开处理。Word／DOC／PDF 中，中文内容通过原文复核后，局部强调映射仍失败时保留已验证中文、主要样式及可确定的强调，逐项提示无法确认的颜色、加粗等；不将这类映射写入已验证断点。样式阶段断连、截断和无效响应均覆盖。PPT 不启用这一后备策略，固定标签格式仍验证标签顺序；中译英翻译校验规则未改动。

已完成的 2.3.5 英译中断点可按原始输入、模型、词库等相同身份读取，但逐项执行当前内容与样式验证。不能把旧断点视为无条件通过。

首次启动校对界面的静态语言选项与初始化状态统一，直接显示“英文／中文”；进入翻译才显示方向。未改变界面尺寸。
