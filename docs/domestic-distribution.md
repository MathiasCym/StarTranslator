# 国内公开来源接入

版本准备、提交、构建、补传和验收统一按 [固定工作与发布流程](../RELEASING.md) 执行。本文件保留国内来源的配置、实现细节及已完成的公开验证记录。

GitHub 继续作为源码和团队词库的维护主仓库。软件可以优先读取维护者控制的 AtomGit / GitCode 或 Gitee 公开仓库，失败后尝试 GitHub。普通用户不需要平台账号或令牌。

目前的 `backend/distribution.json` 已指向 [MathiasCym/StarTranslator](https://atomgit.com/MathiasCym/StarTranslator)。2.0.5 已在国内仓库正式发布：更新信息、校验附件及 143,997,899 字节的完整安装包均已通过匿名读取验证，安装包 SHA-256 为 `5aa7e521d30e717b26002e08640beb4844b9e5f10d3310355b5b57f54946fb65`，与 GitHub 原发行包一致。

2.0.4 和 2.0.5 安装包均通过已登录的发行版页面补传，再进行匿名下载核对后转为正式版。CI 的大文件自动上传仍存在等待响应超时，不能据此宣称后续安装包已能全自动上传；源码和词库同步、已有附件的校验及正式发布流程已通过。本次未重新构建或替换原发行包。

2026-10-15 已用两条实际下载路径验收：2.0.5 下载组件的独立直连会话下载全包用时约 12.6 秒；已安装 2.0.4 的原始更新组件，在独立进程中绕过系统代理，从发现更新、下载全包到安装前复核全部通过，下载约 8.1 秒。后者仅访问 `api.atomgit.com`、`atomgit.com` 和 `file-cdn.gitcode.com`，没有访问 GitHub。没有修改全局代理或执行安装；各地网络速度仍可能不同。

如果此前已发现并开始从 GitHub 下载 2.0.5，需取消原下载并重新检查更新，确认来源为 AtomGit。国内附件尚未完整发布时，旧客户端会回退 GitHub；源码已同步或页面已有版本记录，都不能替代完整附件验证。

### 2.0.5 的更新下载修复

国内更新请求改为使用独立的直连连接，连接失败时再尝试系统网络；GitHub 保留系统网络路径。不更改电脑的全局代理，也不改变模型调用的网络设置。下载中断时先重试同一国内来源，仍失败再核对 GitHub 备用包；所有路径保留版本、大小和 SHA-256 校验。

安装及完整性校验成功后自动清理软件在线下载的更新缓存。Windows 占用安装包时，在新版成功启动并重新核对安装完整性后重试清理。安装取消、失败或组件不完整时保留安装包，方便重试；手动下载到其他目录的文件保留。

这两项修复已包含在正式发布的 2.0.5 安装包中。2.0.4 可直接通过国内来源升级到 2.0.5；2.0.3 的在线更新仍仅支持 GitHub，首次切换国内来源需手动安装 2.0.4 或之后的版本。

## 首次配置

1. 在 AtomGit 创建公开的普通代码仓库。可以通过 URL 导入 `https://github.com/MathiasCym/StarTranslator.git`，也可以使用未初始化 README 的空仓库；公开项目的导入不需要 GitHub 个人令牌。不要启用平台的 Pull / Push 镜像：Pull 镜像会将仓库设为只读，Push 镜像则可能将国内历史反向推回 GitHub。同步方向由下述发布流程统一管理。
2. 将公开仓库的 HTTPS 网页地址交给维护者，运行 `node tools/configure-distribution.cjs <公开仓库网址>` 写入随包来源配置。该工具拒绝带令牌的网址、未知平台和额外路径；配置文件只记录平台及公开仓库名称。
3. 在 GitCode“个人设置 → 访问令牌”创建发布用 PAT，授予所需的项目、代码推送和发行版维护权限。令牌不能来自 GitHub，也不要写入仓库、软件配置、安装包或聊天。
4. 在 GitHub 的 `MathiasCym/StarTranslator` 仓库中打开“Settings → Secrets and variables → Actions → New repository secret”，名称填写 `GITCODE_TOKEN`，Secret 填写 GitCode PAT。使用到期时间；到期后在同一 Secret 中更换令牌即可。
5. 提交来源配置及代码，并在 Actions 中运行 “Sync owned public mirror”。完成后检查国内仓库、团队词库和发行版附件。实际安装包必须匿名下载成功且大小、SHA-256 与 GitHub 原发行包相同，才允许进入软件更新列表。

若免费附件大小或容量不足，国内发布流程会报告失败，未完成的版本保持预发布状态，原 GitHub 正式版本继续保留。先验证平台限额，不购买服务器、不拆分或改造安装程序来绕过限额。

## 后续维护

- 源码仍提交至 GitHub。原有构建、回归、组件完整性和安装引导图像检查通过并正式发布后，再同步国内仓库和发行附件。
- `glossary/team.json` 或 README 的提交会触发镜像同步，不触发完整软件打包。已经同步且校验值一致的发行版会保留，不重复上传或下载其安装包。
- 同步只使用正常的 Git 快进推送，不强制覆盖国内已有分支和标签。若国内仓库包含不同历史，先核对原因，不删除原内容。
- 国内发行附件使用 GitHub 已正式发布的安装包原始字节。同版本重新构建出不同字节时，仍以原正式发行包为准；已经发布且内容不同的国内版本不会被覆盖。
- 安装包上传使用原生 HTTPS，显式发送文件大小；小附件最多等待一分钟，大文件最多等待二十分钟，避免额外的五分钟响应等待限制。上传接口只接受官方签发的对象存储地址，不跟随重定向；传输错误不记录签名网址或上传请求头。非 JSON 回执必须有实际登记的附件，并在正式发布前核对匿名下载后的内容，不能仅凭回执文本判断成功。
- 维护授权仅存在 GitHub Actions Secrets 中。授权请求仅发给 GitCode；上传对象存储使用平台签发的临时上传信息，匿名读取和软件使用不附带维护授权。

## 软件行为

国内来源同时覆盖版本查询、`update.json`、安装包下载以及安装前再次核对发布信息。仅替换安装包链接不能解决版本查询仍依赖 GitHub 的问题。

每个来源使用单独的平台域名校验，拒绝不安全协议、外部跳转、其他仓库的附件、错配版本、缺失元信息和重复附件。下载失败时，备用来源必须与原候选的版本、文件大小及 SHA-256 完全相同；取消任务后清理软件自身的下载临时文件。

词库读取使用国内仓库的不可变提交，核对实际文件的 Git blob SHA，再进入现有差异预览和三方合并流程。比本机已同步版本更早的不同词库不会被采用。确认同步时再次检查预览的来源；来源或内容变化需要重新获取差异，不直接覆盖本机修改。

2.0.4 的词库提交仍读取和写入 GitHub 主仓库，需要原有维护者授权及 GitHub 网络连接。国内仓库恢复可写，代表发布流程可以同步源码和发行附件，**不代表软件中的提交按钮已支持国内写入**。普通用户可以通过国内来源获取词库；同事完全免 VPN 提交的入口尚未实现，不应将下载接入视为该功能已完成。个人材料、模型配置、接口密钥、输出文件和日志不参与镜像同步。

后续国内协作采用专用词库分支：同事配置一次维护授权后提交词库修改，由维护者确认合并；不反向推送整个源码仓库。该方案已确定，尚未纳入 2.0.4 安装包。

Gitee 的匿名读取适配已准备，但自动发布脚本目前只实现 GitCode。HTML 官网的静态页面托管仍单独处理，代码仓库网页不等同于静态网站托管。

## 验收

在自有公开仓库中完成以下验证后再分发包含国内来源的软件：

1. 实际约 143 MB 安装包符合免费附件及容量限额，匿名下载后的 SHA-256 与 GitHub 原发行包相同。
2. 同事关闭 VPN 后，在大陆普通网络下完成版本查询、下载安装前核对、词库差异预览和确认同步。
3. 模拟国内源不可用，检查 GitHub 备用来源；模拟错配版本、错误 SHA 或不完整发布时拒绝安装。
4. 维护者提交新词，观察 GitHub 主仓库提交、国内同步、普通用户获取，确认未覆盖本机独立编辑。
5. 确认原翻译、校对、对照、历史、安装完整性和局域网协作回归检查通过。

旧安装包不会自行获得新增来源；首次切换需安装含已验证来源配置的版本，之后才能使用新的更新路径。
