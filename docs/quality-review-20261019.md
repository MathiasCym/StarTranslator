# 翻译与校对质量复查（2026-10-19）

本轮以 2.0.14 正式源码为基线，按“输出质量优先、输出有效文件优先”的要求检查流程。改动进入 2.0.15 发布批次；2.0.14 原安装包不改写。本轮只使用独立测试材料和本机假模型，不发送真实文档。

## 已确认并修复

1. **数字相同可能掩盖单位错译。** 原校验能保护数值、日期与型号，但 `亮度500尼特` 对 `Brightness 500 mm` 仍可通过。新增数值与常见物理单位绑定检查，识别尼特、长度、频率、帧率、bit、pixel 等明确单位；正确的单位别名、`500 × 600 mm` 共用单位和区间写法不会因此失败。中文“位”“块”等量词继续结合语境处理，不强行套用 bit 或 screen。出现问题仍走有限修复和局部待核对流程，不阻塞其他段落与有效文件保存。
2. **无效校对条目可能被算作完整检查。** 原模型清洗会丢弃不属于当前段落的条目，剩余空列表可被记为检查完成；`null` 替换文本还可能被转成字面字符串。现在无效结构或原文不对应当前段落会触发该段有限重试；持续无效时明确标为未完成，不冒充“无错误”。可单独调用的批量兼容函数也不再把错误段落视为已覆盖。
3. **校对阶段仍合并多个段落请求。** 这会让一个响应同时承担最多 8 个段落的审校与定位，覆盖检查只能证明返回了编号，不能证明每段得到足够关注。生产校对流程改为每段独立请求，保留完整页内语境、参考资料、已确认术语和重复用语提示；并发仅用于重叠独立请求，不合并任务。代价是请求数可能增加，不承诺真实模型一定更快或所有语义问题都能发现。
4. **新规则下继续复用已有成果。** 保留 2.0.14 翻译断点身份兼容，复用前重新执行新内容及单位校验。正确结果直接复用；错误单位的旧译文重新处理，不通过更换版本来绕过质量关口。校对策略变严后的旧校对缓存不直接冒充新规则下已检查。

## 保留的质量机制

- 按原段落和局部样式边界翻译，工作线程不直接修改 Office XML；颜色、加粗、字体和图片保持原有写回与检查流程。
- 翻译带整页语境、对应材料及术语数据，数字、日期、型号、残留中文和样式映射继续验证；错误先有限修复。
- 断连或局部失败保留文档与断点；已完成英文继续校对，未译中文明确列出，建议仍由用户确认后应用。
- PPT 本机排版、逐页图像审查和新增遮挡验证继续保留；本轮没有减少渲染或格式处理阶段。

## 尚未由本轮解决的质量空间

- **语义等价。** 否定、限制条件、因果、宣传用语、角色关系等仍主要靠模型结合原稿判断；数值与单位通过不能代表全文内容忠实。后续可用实际失败案例评估有针对性的二次忠实度复核，避免无差别重复翻译。
- **模型视觉能力。** 本机几何检查不能代替整页视觉判断；文本模型或视觉接口不支持时，现有提示必须继续保留，不能宣称模型已经看过页面。
- **复杂单位换算和歧义。** 本轮不自动推断模糊日期或单位，也未新增物理单位换算。原有数值校验仍可能要求模型保留原始计量方式；更广的换算需同时验证数值、单位及维度，避免机械替换。

验证的实际结果、日志与界面截图记录在 `dist/qa/quality-next-record.md`。源码测试通过不代表已打包、安装或公开发布，也不等同于真实模型在所有业务材料上的质量保证。
