维护者于 2026-10-20 要求以下问题留到下一版处理。随后指定与文档质量修复、人名分类一并整合到 2.2.0；已发布的 2.1.9 保持原样。

- [x] 修正翻译进度下方“模型正在翻译第 xx 段”的失真提示。累计完成数量、待翻译段落总数和原稿定位编号必须分别表达，不能将不同含义的编号混在一起；原稿定位无法准确提供时，不显示貌似精确的段号。
- [x] 提示必须反映真实阶段：模型请求、等待响应、内容校验、样式写回、断点复用及重试分别显示；命中已验证断点时不能声称模型正在翻译。并发处理不能用某一个工作线程最后写入的提示代表整个任务，应显示实际活动状态与累计完成量。
- [x] 验证顺序与并发、断点复用、重试、不同文档结构及桌面/局域网端；不得为使编号看起来顺序增长而伪造进度或影响翻译质量。

原问题与实施线索：`backend/translation.py` 的 `page_worker` 在读取断点前即推送“模型正在翻译”消息，并直接显示 `seg.para`。这是原稿定位信息，与已完成的待翻译段落数量不是同一口径；并发工作块还会覆盖同一个任务提示。实施时同时核对工作流进度事件与界面显示，不只替换一句文案。

2.2.0 使用 RequestActivity 记录真实请求前后状态，并汇总并发活动；断点先校验再复用，不再显示模型正在翻译。tests/test_translation_recovery.py 验证实际事件、累计数量及完全复用时没有伪造请求提示；桌面与共享端共用工作流事件。
